Security and standards

  • Passwords are stored as bcrypt hashes and can't be read back.
  • Emails and support ticket text are encrypted in the database with AES (Fernet). Names, roles and climate data aren't.
  • Connections through Apache use TLS 1.2 or newer. The local certificate is self-signed, so browsers show a warning.
  • Repeated failed sign-ins are blocked for 15 minutes.
  • Dates use ISO 8601, and map exports use GeoJSON (RFC 7946).

These follow common practice, such as the OWASP guidance on password storage. The system hasn't been independently audited or certified against any standard.

Architecture

Public datasets are downloaded and stored in HDFS. Python jobs run on YARN through Hadoop Streaming, and their results are loaded into MongoDB. A FastAPI backend applies login and roles, and serves both this dashboard and the data. Models train in Python on the results in MongoDB, and every run's scores are saved.

Browser → Apache (HTTPS, load balancing) → Two FastAPI instances → MongoDB

NOAA, NASA, OpenAQ → HDFS → MapReduce on YARN → MongoDB → FastAPI → Dashboard

MongoDB → scikit-learn, statsmodels → MongoDB (scores and forecasts)

Open-Meteo → Collector service → MongoDB → Alert rules → Email and notifications

Collector service → Hourly CSV batches → HDFS

Live data is collected on a timer, not through a streaming system such as Kafka. Each new value is available within one collection cycle.
